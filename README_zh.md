# anything2explainer-lite

[English](README.md) | **简体中文**

> 给一个主题，产出一条**黑底 MG 风格**（星点雾底 / 点阵波）**科普讲解视频**：TTS 配音 + 逐词字幕 + 章节进度条，中文或英文，每一帧都由 Remotion / React **代码**绘制。
>
> 本档是 [`anything2explainer`](https://github.com/Vincentwei1021/anything2explainer) 的**低成本档**：**读清单 −76%、图像重放 −99.8%**。省下的成本全部来自"同一张图被反复重看"，副作用是审美反馈变成**开环**，因此用**四根零图像成本的机器门禁**把质量重新约束回来。

## 1. 这是什么

**做什么**：输入一个主题 → 输出一条成品 MP4。中间产物齐全：研究简报 → 分镜表 → 逐镜 TSX 源码 → TTS 配音 → 字幕 → 四轴门禁报告。

**怎么定位**：上游 `anything2explainer` 的质量很高，但**每个构建组每次派单要读 39,478 token** 的协议文件；真正贵的是**图像重放**——全片 15 个镜头、每镜 6 张全尺寸 still、边做边看，累计 **8,295,750 token**。

**本档做的事**：把这两笔账砍下来，同时**不把质量交给运气**——用机器门禁替代被砍掉的人眼。

**同时是 Windows 友好移植**：上游 5 个 shell 脚本是 `#!/bin/zsh`（依赖 `rsync`、BSD `sed`、zsh 数组），在本档改为等价的 Python 实现，`.sh` 仅作兼容入口保留。详见 [`WINDOWS-PORT.md`](WINDOWS-PORT.md)。

**不是什么**：

- 不是上游的官方精简版，改动逐条列在 [NOTICE](NOTICE) §1；
- 不是"全部缩水版"——门禁是**只增不减**的（4 根 > 上游 3 根）；
- 不擅长垂直 9:16（全档假定 1280×720 横屏）；
- 不保证审美细节追平上游（见 [§8 已知限制](#8-已知限制必须主动告知使用者)）。

## 2. 成本是怎么压下来的（三个杠杆）

| # | 杠杆 | 上游 C0 | 本档 | 机制 |
|---|---|---|---|---|
| **A** | **派单读清单** | 5 份 reference + `ui.tsx` **全文** + `fx.tsx` + **项目全文**<br>**39,478 tok / 组** | `build-contract-lite.md` + `api-index` + `common-api` + `types.ts` + **本组 3 份切片**<br>**8,833–9,412 tok / 组** | 与其"读完全部再动手"，不如**读契约 + 按组切片**。构建组不需要知道别的组在画什么 |
| **B** | **看图（still）** | 1.0 尺度（1280×720）· **6 张/镜**（高光 ≥10）· **边做边看** | 0.25 尺度（320×180）· **2 张/镜** · **生命周期尾部一次看完** | 账本 B 里真正贵的**不是图像面积，是"读完之后还剩多少轮"**。C0 是 75 轮（每张图要在后续 75 轮里重复计费），本档是 8 轮 → **尾部加图比开头加图便宜 9.4 倍** |
| **C** | **补回质量** | — | **四根零图像门禁** + 三条硬规范 | 被砍掉的是"人眼兜底"，那就把**只有看图才知道的几何事实，变成源码里可读的数字** |

杠杆 C 的逻辑值得单独说一句：

> **遮挡不该靠"看清楚"，该靠"算得出"。** 而"算得出"是**文本**成本，比图像便宜 2–3 个数量级。

## 3. 压缩效果（实测，口径见 `measure.py`）

> **样本口径**：以下全部读数来自同一部对照实验片《HTTPS（TLS 1.3）握手为什么只要一次往返》（**15 镜 · 1280×720 / 30fps · 3 个构建组**），两档用同一套 `measure.py` 口径测同一批文件。**它不是"任意主题都能复现"的通用基准**，但组化切片是线性的，量级可外推。

### 账本 A｜协议侧必读清单（token / 次派单，每「组」一次）

| | G1 | G2 | G3 | 全片 | 相对 C0 |
|---|---|---|---|---|---|
| 上游 C0 | 39,478 | 39,478 | 39,478 | **118,434** | — |
| 本档 C2F 实测 | 8,833 | 9,412 | 9,301 | **27,546** | **−77%** |
| + 门禁条文（判据 260 + 量尺 60 + 审计报告 170） | 490 | 490 | 490 | 1,470 | — |
| **本档 + 优化** | 9,323 | 9,902 | 9,791 | **29,016** | **−76%** |

预算 11,500/组 → 三组全部达标（余量 2,088 / 2,199 / 2,667），且**成本近似线性可加**（三组同时上档不会因组间耦合而退化）。

### 账本 B｜图像重放代价（全片 15 镜）

| 口径 | 原图 tok | 重放轮次 | 合计 tok | 相对 C0 |
|---|---|---|---|---|
| 上游 C0（6 张全尺寸/镜，边做边看） | 110,610 | 75 | **8,295,750** | — |
| **本档 C2F（2 张 0.25/镜，尾部看）** | 2,310 | 8 | **18,480** | **−99.8%** |

**两个账本合起来**：读清单 **−76%**、图像重放 **−99.8%**。而把遮挡重新变成"可被门禁拦住"的缺陷，只花了账本 A 的 **+5.3%**、账本 B **零增量**。

### 质量侧：砍完之后没崩

| 指标 | 上游 C0 | 本档 C2F |
|---|---|---|
| 持续动作（静止率均值 / 最长静止） | 14.3% / 0.9s | **6.7% / 0.5s**（更优） |
| `frame_metrics` 高/中/低 | 1 / 0 / 13 | **1 / 0 / 10**（低档少 3 条） |
| 逐镜头 改善/退化/持平 | — | **5 / 3 / 7**（净改善） |
| 复用 C0 画面帧 | — | **14.6%（仅外壳层）** → 全片独立生产 |
| `zorder_audit`（15 镜） | 无此轴 | **命中 2 条（皆"高"）/ 其余 14 镜零误报** |

## 4. 质量怎么不崩：四根零图像门禁

| 门禁 | 治什么 | 成本 |
|---|---|---|
| `zorder_audit.py` | **层序倒置**（后入场的元素被先入场的实心块压住）、同帧叠字、**可审覆盖率** | 零图像 token，秒级 |
| `selfcheck.py` | 帧覆盖空洞、闪烁白名单超标、画面字面量与事实不符、分镜表与源漂移 | 零图像 token |
| `frame_metrics.py` | 主体墨迹 / 柔光 / 紫色碎片等像素读数 | 零图像 token |
| `lite_gate.py` | **一条命令跑完四轴 + 一个退出码**，让"跳跑"在结构上不可能发生 | 零图像 token |

配套三条新硬规范（`reference/build-contract-lite.md` §12–§14）：

1. **层序纪律** —— 入场序 = 绘制序（源码次序即屏幕叠加次序，本档不用 `z-index`）；
2. **坐标须字面量** —— 禁止 `x={fn()}` / `cx={MAP[i].cx}` 这类表达式，这是**可审计性的前提**；
3. **交付补列** —— 主体墨迹盒 / 最大重叠 / Z1·Z2 命中必须写进 `BUILD_NOTES.md`。

**样例（真实命中）**：SC06 在 23.0s 处，后入场的「TLS 1.3」被先入场的论文卡压住，墨迹重叠 39×150px = 5,850px²；像素验证该处墨迹从 54.3% 掉到 1.3%（−53pp，字心对照带只差 1.2pp）。审计器不仅报出，还直接给出"要移多少像素"。

**门禁的诚实设计**：`lite_gate.py` 在 rc=1（不通过）或**未知**时都算失败；`zorder_audit` 覆盖率 <90% 时报"覆盖率不足"而**不给假的通过**。"未跑"是一个**独立状态**，不等于通过。

## 5. 快速开始

```bash
# 0) 确认安装完整（无外部依赖；应输出「独立性自检通过 ✓」）
python scripts/lite_bootstrap.py --check

# 1) 起项目（复制引擎 → npm install → tsc）
python scripts/lite_bootstrap.py D:/a2e/my-video myvideo

# 2) 按 SKILL.md 的五阶段流程走（主会话编排 + 构建组并行）
#    派单只给 6 份文件（见 reference/prompts-lite.md §0）

# 3) 每组收组前跑门禁（零图像成本，几秒）
python scripts/zorder_audit.py src/shots --gate

# 4) 成片渲染后跑四轴总门禁（rc=1 不得交付）
python scripts/lite_gate.py --require-final
```

**环境提示**

- Windows 下**不要用 `python3`**（可能解析到 Microsoft Store 占位程序）；用你的 venv 解释器，或用环境变量 `A2E_PYTHON` 指定；
- 项目放**短路径**（如 `D:/a2e/xxx`）—— `node_modules` 会撞 260 字符 `MAX_PATH`；
- 磁盘留 **≥5 GB**；
- `npm install` 会拉 Remotion（见 [授权与致谢](#9-授权与致谢)）。

**完全独立**：下载即用，不依赖任何其他 skill。引擎（Remotion 工程 17.6 MB）、示例资产（样片全套 + 反例）、参考文档、门禁脚本全部自带。

## 8. 已知限制（**必须主动告知使用者**）

1. **审美反馈是开环的** —— 构建组看不到全尺寸图，"细节不够完善"这类**先验驱动**缺陷比完整版更可能残留。
2. **像素级遮挡抓不到** —— `zorder_audit` 判的是**几何相交**；"柔光把邻元素洗淡"这类**像素级**问题（如大面积紫柔光在物体边缘形成实心环）它看不见，属**未验证项**。
3. **覆盖率依赖代码风格配合** —— 实测可审覆盖率 **74.0%**（已解析 37 / 内容对象 50），盲区来自对象属性引用这类非字面量坐标；这正是 §13「坐标须字面量」要治的病。覆盖率不足时门禁**报错**，而非给假的通过（刻意设计）。
4. **字幕折行 / 节奏 / 音画同步**无机器轴覆盖，必须人工审片（清单见 `reference/qc-lite.md` §6）。
