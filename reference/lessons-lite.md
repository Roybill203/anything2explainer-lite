# 必读教训（lite 档摘录）

> 这是从主 skill 的 `reference/lessons.md`（约 68K）里摘出的、**与「减少 bug」直接相关**的部分。
> 全量版在制作过程中会越滚越大，lite 档只带这些。**每条都是真踩过的坑，不是理论。**
> 排在前面的，是 lite 档最容易复发、代价最高的。

---

## A. 遮挡 / 层序（lite 的头号缺陷类）

**A1. 「后出现的元素被先出现的实心块盖住」是逻辑错，不是审美错。**
机制：**DOM 里排在后面的画在上面**，与入场时间无关。所以「后入场却排在前面」= 被压。
EXP-01 实例：C2F 的 `SC06`（21.13–25.87 s），论文卡入场 642 排在主角「TLS 1.3」入场 666 **之前** → 用户在第 23.0 秒看到"主角从图层背后冒出来"。
像素级坐实：帧 690/696 的「抢墨带」白墨迹 **C0 54.3% → C2F 1.3%（−53pp）**，而字心对照带只差 1.2pp → **排除运镜，就是被卡吃掉了**。
→ 规矩：**入场序 = 绘制序**（`build-contract-lite.md` §12）。

**A2. 照抄历史修复值是危险动作。**
C0 版 `SC06` 的注释里明明白白写着「实测主角 x314–936，卡片 850–1149，重叠 86px」，并把卡右移到 **910**。C2F 把卡放回了 **880** —— 但即便照抄 910 **仍然重叠 9px**，因为 C0 的主角字距是 0（墨迹右缘 908）、C2F 的共用件字距是 3（**919 > 910**）。
→ **必须在当前实现上重算**（`zorder_audit` 会直接给要移多少像素）。算出来的解：`PaperCard x=930 w=270` → 重叠 0px。

**A3. 「0 命中」不等于「干净」。**
同一个审计器在 **C0 源码上也是 0 命中，但那是假的**——C0 用 wrapper 局部坐标（`left: 910` 包 `<PaperCard x={0} y={0}>`）、主角写 `<CText cx={HERO.cx}>`，**全落在"未解析"里，主角根本没参与计算**（`C0_G2` 覆盖率仅 63.2%）。
→ 覆盖率是**门禁的一部分**：**低覆盖率下的"干净"没有任何证据力**。C2F 覆盖率 74.0%（37/50 内容对象）。

**A3b. 注册表救不了「对象属性访问」，只有扁平字面量才行（实测）。**
C2F 的盲区实测分类：单加一条 `zorder_parts.json`（登记 `BigNumber`）→ **74.0% → 80.0%（仅 +6pp）**；剩下 10 个盲区**全是**
`MsgCard x={CARD.x + cardDx}`（**动态偏移**）、`ClientBox cx={CLIENT.cx}` / `Envelope`（**对象属性访问**）——
**静态不可解，注册表救不了，必须把几何抽成扁平局部常量**（`const CARD_X = 420;` → `x={CARD_X}`）。
→ **注册表是补丁，坐标扁平化才是解药。** 覆盖率上不去时，先怀疑源码写法，不要怀疑审计器。

**A4. 判据换成「层序倒置 + 相交」才可用。**
前作 `layout_audit.py` 自评精度只有 **29%**（源码级静态版面审计）。这次能用的原因：① 判据从"越界"换成"层序倒置 + 元素相交"；② 字宽用**真实字体**实测（`ImageFont`），不靠估；③ 退化矩形**静默剔除**（宽<20 或高<16 一律不计入，避免假阳性）。**假阳性会把真阳性一起埋掉。**

## B. 方法（比单个 bug 更值钱）

**B1. 压缩会优先伤害那些「只有人眼兜底」的判据。**
C2F 在"持续动作"这条**有机器门禁**的规则上做得比 C0 更狠（静止率 6.7% vs 14.3%），代价全落在"遮挡"这条只有人眼看的规则上。
**被量化的指标被优化，没被量化的被牺牲——而压缩恰恰就是"减掉测量手段"的动作。**

**B2. 没覆盖比误报更危险——误报至少会响，没覆盖是无声的。**
EXP-01 里 C2F 报了"通过"，但三根轴**都看不到"元素互相遮挡"**。而实验方案里第一行判据就是「遮挡/溢出/字号」，标注"原本靠 agent 看图"，替代方案写的是"元素 bbox vs 安全区"静态检查——**那个检查器从来没被做出来**。
→ **是被拿掉了，不是被漏掉了。** 下结论前逐条对着预注册判据标「这条由哪个轴覆盖」，没覆盖的必须写"**未验证**"，不许默认通过。

**B3. 先判断缺陷是「先验驱动」还是「验证驱动」，再决定压哪个。**
- 先验驱动（细节不够完善、不知道图元真实外沿）→ **多给知识**（完整规范 / api-index / 参考帧）能治。
- 验证驱动（推近后有没有压边、光斑有没有盖住邻元素）→ **只有看清才知道**，多给知识治不了。
→ 别指望靠减读清单治好第二类。

**B4. 「成本线性可加」要单独验证。**
上一轮只测 G2 单组（−76%），无法回答"三组同时上会不会因组间耦合而退化"。全片实测三组各自达标（−78% / −76% / −76%，全片 **−77%**）→ 答案是不会。
**多组并行的实验，务必在"全片尺度"上再报一次总账。**

**B5. 结论要能复现，别把 ±1 当结论变化。**
全片逐帧差异两次独立跑得 1618/278 与 1619/277（**±1 帧**）——阈值附近的帧会在生死线上抖动。报告里要写明。

## C. 度量与数据（喂错数据，度量器再准也没用）

**C1. 输入目录是实验数据，必须先证明它属于哪一版。**
曾有一份 `frame_metrics_C0.md` 跑在**混装多个版本残留帧**的目录上，把"低 13 条"错报成"低 14 条"。
→ 凡"从渲染产物反推数字"的度量（`frame_metrics` / `motion_check --frames` / 逐帧差异），先写脚本从 mp4 **现解帧**做来源核验（逐帧 vs 抽帧目录的均差 mad 应 ≈0）。
**度量器再确定，也救不回喂错的数据。**

**C2. `frame_metrics` 的「高」是相对量。**
它的"主角"是**最大物体单选取** → 双大物体镜头必误报；「紫色碎片 <8」与「主角区柔光 ≥800」**互相耦合**（任何过阈值的紫柔光都会在柜边形成 ≥80px 实心紫环，两条阈值同时被触发）。
C0 基线本身就有 1 条"空场"高。→ **只报告不门禁**，逐条人工裁定；**不要为了消掉它去改判据**（判据一松就再也拦不住真的空场）。

**C3. `motion_check` 的判据是面积归一化的。**
奖励"大面积微变"，几乎不给"小面积大变化"分：整屏卡片滑入 0.4–2.1；3px 虚线 / r=6 光点 / ±6px 浮动只有 0.07–0.25。
→ **以细线、小点、小字为主的稀疏镜头，唯一可靠解是整帧慢推**（稀疏镜头 1.0→1.08，元素密集 1.05）。
→ **组级读数偏松**（低分辨率渲染），**成片 `fin_frames` 复测才是判据**。

**C4. `nb_frames` 会被音频流覆盖。**
`ffprobe` 不带 `-select_streams v:0` → 音频 2965 帧 vs 视频 1896 帧，差点误判成片规格。

## D. 工程（会让你白干半天的那种）

**D1. 禁用 `npx remotion still`。** 它建**临时 bundle**，曾把磁盘写满。一律用 `scripts/still.sh`（一个组只留一个 bundle，tag 固定 `gN`）。

**D2. 并行构建组的前置条件**（三条缺一不可）
- 各组的 `index.ts` 先放**空占位**（免得 A 组的镜头进了 B 组的 bundle）；
- **不要加 `--reuse`**（会跨组复用 bundle，造成产物污染）；
- 各组的 bundle tag **互不相同**（`g1` / `g3`）。

**D3. MSYS 路径静默进错目录。**
`os.path.abspath('/d/a2e/x')` 在 Windows 上 → `D:/d/a2e/x`。G3 agent 因此把 still 写到了错位目录树，**没报错**。
→ 凡接收命令行路径的脚本，先过 `_env.winpath()`。已修进 `still.py`。

**D4. `GLOW_*` 常量含 spread（4 个长度值）→ 只能当 `boxShadow` 用。**
当 `textShadow` 用时**整条声明被浏览器静默丢弃**——`tsc` 不报、静止帧也看不出。text-shadow 只能 3 个长度，要发光就自己展开。

**D5. 硬切前必须归零。**
单用 6.7%/帧 的 `exitFade` 做硬切前，**末帧还剩 40–60%** → 观感"啪"一下。用 `1−(n/N)^1.5`、N=6–12、末帧为 0。
相邻镜头**不留空白帧**（允许 0–3 帧重叠）；分镜表两侧都要写清「A 末 8 帧归零淡出 + B 首帧起 SoftIn」，**不要只写"硬切"**（会各自理解为"我不动" → 6–8 帧空场）。

**D6. 分镜表可能自相矛盾。**
本片分镜的「动效」格给 SC11 写了 2 处、SC12 写了 2 处、SC15 写了 3 处 glitch，而**全局约束规定每镜头 ≤1**。
→ 真值以**全局约束**为准；改规格时**只改 `script/storyboard_src.md`**（`分镜表.md` 是它的函数输出），并在规格留痕里写明修正原因。改完数一遍每行格子数（必须 7 格）。

**D7. 选帧公式必须显式。**
"入场完成帧" = `from + 入场时长 + 余量`，**要写出来**。曾用 `from+8` 取到空帧（元素还没入场），白看一轮。

**D8. 派单时明确"只改本组"**，并让 agent 把共用层建议写进 `BUILD_NOTES.md`——否则会有人顺手改 `ui.tsx`，把别的组一起改坏。

## E. 交付纪律

1. **有列才有承接。** C0 的构建者算过重叠、写进了注释——但**没有列可填**，信息没进交付物；换一版重建时**没有任何机制把它带回来**，同一个 bug 精确复现。→ `BUILD_NOTES` 必有「主体墨迹盒 / 最大重叠 / Z1·Z2」三列。
2. **有 `[高]` 先修再交**，不要留给 QC。
3. **收组结论显式写**：层序命中 高N/中M · 可审覆盖率 P% · 未解析清单（为空写"无"）。
4. **每改一次几何，重跑一次 `zorder_audit.py --gate`**——挪开一个元素可能把它压到另一个元素上。
