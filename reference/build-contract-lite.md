# 构建契约（lite 档）

> 本文件是**本 skill 唯一的构建契约**：把画风 / 动效 / 构图 / 持续动作 / 性能 / 自检等硬约束合成一份，供构建组替代全量必读。
> 被省略的是：指标对比与背景、示例式解说、图元 props 细节（→ `api-index.md`）、
> 解说词/配音（阶段 2）、分镜写法（阶段 3）。各条目的完整解释见本 skill 的 `style-guide.md` /
> `motion-vocabulary.md` / `composition-and-light.md` / `narration-storyboard.md`。
> （完整版的 `build-contract.md` 与 `agent-build-rules.md` **有意未打包** —— 它们是 C0 语义，与"少看图"直接冲突。）

## 0. 工程约定

- 工程 = `<项目根>`（Remotion 4 + React 19 + TS，1280×720@30fps）。下文 RAG/ 指 `<项目根>/`。
- 帧号 **N = useCurrentFrame() + F0**（F0 = 该镜头 `ShotDef.from`，1 起含端点）。分镜表与 timeline 里的帧号都是 N。
- **只改 `src/shots/Gn/**`**。不改 Main/Root/common/overlay/其他组。共用层要改的写进 `BUILD_NOTES.md` 并在最终回复提出。
- 每镜头一个文件 `src/shots/Gn/SCxx.tsx`；`index.ts` 导出 `SHOTS_Gn: ShotDef[]`（`{id,from,to,Comp,layer?}`，**数组顺序即层序**）与 `BG_Gn: BgSpec[]`。
- 动画一律是 N 的纯函数，**不用 useState/useEffect 做动画**；随机只用 `rnd(...seeds)`，禁 `Math.random`。
- 字体由 Main 全局加载（Noto Sans SC 100–900、Exo 2 Italic、Audiowide、Orbitron），组件内**不要** delayRender 加载字体。
- 常驻层由 Main 渲染：黑底 < 幕底 < 镜头 < 进度条 < `layer:'aboveBar'` < 字幕。**镜头不要画不透明黑底**；确需纯黑/无星用 `BG_Gn: [{from,to,fog:false,stars:'none'}]`。
- import：图元 `'../../ui'` · 光效 `'../../fx'` · 共用层 `'../../common'`。

## 2. 视觉体系（速查）

- 底：黑 + 雾底（y415→687 #000→#212121）+ 星点（80 颗 2–4px，漂移 0.4–3.2px/帧）；或 `config.bg='dots'` 点阵波（互斥）。
- 图形语言：黑填充 + 白描边 2–3px，或紫/橙纯色块 + 白描边。中文超粗黑 Noto 900（scaleX .8–.85）；英文技术词 Exo 2 紫斜体。参考帧 `examples/rag/frames/ref_*.jpg`（先看再画）。
- **颜色即语义**：紫=重点/我们的 · 灰=未激活 · 橙红=指标/警示/对方 · 白=结构文字 · 绿=正确。一帧紫重点 ≤1 处大面积。
- 调色板：`PURPLE #6630F8`（重点/激活/品牌）· `PURPLE_LIGHT #A175F1`（高光端/active 卡边）· `PURPLE_TECH #6530F4`（Exo 技术词）· `PURPLE_DEEP #5A3AD5`（曲线/硬投影）· `ORANGE #F05F41` / `CORAL #F16043`（指标/警示/对方）· `RED_DEEP #EC081F`（深红警示）· `GREEN #8FF740`（勾）· `GREY #A0A0A1` / `GREY_MID #747474` / `GREY_LINE #4A4A4A` / `GREY_LIGHT #D4D4D4` · `WHITE #FFF` · `MAGENTA #D100D6` / `CYAN #58FFEE`（**只给 glitch RGB 错位副本**）。
- **尺寸只有三档**：主角 ≥170px（或大字 ≥96px 且整行宽 ≥300）／配角 60–110／标签 22–30。**配角 ≤4、标签 ≤6**，三档之外不出现第四种尺寸。
- 尺寸速查：手机 mock ≥300×520 · 人形 ≥96 · 机箱/DB/文档卡 ≥160 高 · 书/考卷 ≥240 宽 · 公式主项 ≥48、结果项 ≥72 · 年份/大数字 96–150 · 图表卡 ≥440×300。**卡 150×92、Pill 150×44 是配角尺寸，不能当主角。**
- 字体：标题 Noto 900 56–96px scaleX .85 · 胶囊/标签 24–30/600–800 · 说明 22–26/500–600 · 宽体大写 Audiowide 96–150 + 紫硬投影 6px · 数字 Orbitron 24–110。

## 3. 光（只有三层、三色）

- 层次：白 bloom（结构线条常驻）< 紫柔光（主角常亮 + 当前重点）< 白闪（事件 3–6 帧）。颜色只用**紫/橙/红**。
- **主角必带光**：图形 → `GLOW_PURPLE` / `HeroGlow` / 脚下 `HaloRing`；大字 → `TEXT_GLOW` + `6px 6px 0 PURPLE` 硬投影；Noto 900 大字 → 1–2.5px 紫描边 `paintOrder: stroke fill` + 紫柔光；橙色指标数字 → `GLOW_ORANGE`。
- **配角不发光**：胶囊/流程轨/标签/表格/说明默认无 glow；**一帧内 `GLOW_PURPLE_S` ≤1 处**（当前重点那一枚）；重点转移时前一处 8 帧灭掉。
- 光要动：主角光呼吸 **30 帧周期 ±15%**；重点激活 α 0→1 走 8 帧；离场**先灭光 6 帧**再整体淡出，不带着满光硬切。
- ⚠ **`GLOW_*` 常量含 spread（4 个长度值）→ 只能当 `boxShadow` 用**。当 `textShadow` 用时**整条声明被浏览器静默丢弃**（tsc 不报、静止帧看不出）。text-shadow 只能 3 个长度；要在文字上发光就自己按 3 长度展开。

## 5. 动效帧数速查

**入场**：`SoftIn` 8 帧（**一切文字/标签/HUD/小图标的默认**，`fadeIn(0)=0` 会空一帧，首帧用 `firstOp`）· `GlitchIn` 12 帧透明度模板 `[.5,1,.5,0,.5,0,.5,1,.75,.5,.75,1]`（**每镜头 ≤1 处**，只给重点词）· 自下滑入 `y=yEnd+Δ·(1−n/22)^2.5` 22 帧 **Δ≤120**（Δ300 会穿字幕带）· 侧滑 18 帧 Δ260–320 · 缩放 `scaleIn(n)` 21 帧 · 错峰 2 帧/个（**不要用 GlitchIn 错峰**，像掉帧）· `LineArrow p={clamp01(n/20)}` 16–28 帧（箭头自根部长出）· draw-on 框 stroke-dasharray/clipPath 20–30 帧 · 打字机 2 帧/字 · 计数 14–26 帧 · 逐行 wipe 2 帧/行。

**强调**：脉冲 `emphasisPulse(n,{peak:1.11,up:13,hold:4,down:13})` 30 帧 · 灰→紫 `mix(GREY,PURPLE,clamp01(n/11))` 11 帧（边框与填充同变）· 柔光亮起 α 0→1 8 帧 · 白闪 brightness 1→1.6→1 6–10 帧 · 高亮条 wipe 12 帧。

**离场**（**硬切前必须归零**）：归零淡出 `1−(n/N)^1.5`，N=6–12，末帧 0 · 加速下摇 `exitAccel(n,c)` c 0.2–1.2 配归零淡出（旁有字幕带时限幅 ≤10px）· 左滑 12–15 帧 · 变灰下沉 12 帧。**禁止**单用 6.7%/帧 `exitFade` 做硬切前（末帧还剩 40–60% 会"啪"）；可见度 >20% 时 Sequence 就结束。相邻镜头**不留空白帧**（允许 0–3 帧重叠）。

**运镜**（`CameraRig` / `camAt`；**每章 ≥3 次、每镜头 ≤1 次**）：定点推近 1→1.33 / 33 帧（bezier(.6,.05,.4,.95)）· 拉远/拉回 37–45 帧 · 承接位移 16 帧 `easeInOutPow(2.5)`（上一镜头主角缩到 0.6 移到角落，**两镜头共用同一组件同参数**）· 整组平移 20–30 帧 · 整页滚动 43 帧 · 视差 2–3 层（背景层压暗 ×0.43）· 加速出画 12–25 帧 · 甩出 1–3 帧（一章 ≤2 次）· 屏幕空间暗角 顶/底 `linear-gradient` 黑 α .38–.42 淡入 18 帧（推近时同步，压注意力到中央）。
**高亮运镜**（定点推近 / 拉远 / 甩出）期间**不做 GlitchIn、不做错峰入场**（**先入场、停 ≥10 帧再动**）；顶部 HUD / 流程轨 / 字幕在屏幕空间不动（**只动内容层**）；**scale ≤1.33**。
**贯穿慢推例外**：§6 兜底那种 1.0→1.05~1.08 全程缓推**不受上一条限制** —— 它的作用就是填满入场之后的静止时长，**与入场、GlitchIn 并存是常态**。若按高亮运镜的限制去做，含晚入场元素的镜头会把推近起点逼到片尾、留下 >40 帧死区（实测 SC09 因此把起点设到 1072，留 24 帧真静、静止率 44%）。

**节拍**：元素出现 = 对应字幕块起始帧（`timeline.md` 每个 `｜` 块），容差 **−6…+3**；每句至少一处可察觉变化。
**衔接**：分镜表两侧都写清（「A 末 8 帧归零淡出 + 轻微下摇；B 首帧起首批 SoftIn」），**不要只写"硬切"**（会各自理解为"我不动、你从节拍帧才入场" → 6–8 帧空场）。相邻 Sequence 允许 0–4 帧重叠。

## 6. 持续动作（§9 —— C2 档最硬的一条）

- **每个字幕块讲的动词，画面上要有一个持续到下一拍的动作**：数据流 / 脉冲光点沿箭头跑 / 逐行打字 / 逐格点亮 / 生长 / 旋转 / 闸门开合 / 队列压紧。
- 元素入场后**不许完全静止 >30 帧**（**柔光呼吸不算**）。
- 没有其它运镜的镜头加一次 **1.0→1.05 慢推**贯穿（算该镜头的一次运镜）。
- 判据（`scripts/motion_check.py <Gn>`）：内容区 320×180 逐帧灰度平均变化 **<0.35 记静止**；每镜头静止 **≤40%**、最长静止 **≤1.0 s**（构建目标 ≤0.7 s）。**成片 `fin_frames` 复测才是判据**（组级低分辨率渲染偏松）。
- `--frames` 模式多一列「最长静止段内全分辨率变化像素」：**<800 真静**（→ 加动作）｜**800–2500 小面积动作**（→ **加大幅度**：运动元素更亮更大更密、主角本体 30 帧呼吸 ±2%，**不是加元素**）。
- ⚠ **该指标是面积归一化的：奖励"大面积微变"、几乎不给"小面积大变化"分**。整屏卡片滑入 0.4–2.1；3px 虚线 / r=6 光点 / ±6px 浮动只有 0.07–0.25。**以细线、小点、小字为主的稀疏镜头，唯一可靠解是整帧慢推**（幅度按内容定：稀疏镜头用 1.0→1.08，元素密集的 1.05 即可）。

## 7. 背景与纵深

- **背景只有幕底**（星点或点阵波），不撒小图标做氛围；表现「多」用 **≥6px 方点阵列/网格**，整齐排布、按节拍点亮。
- 空间/层级/索引 → `TiltPlane` 叠 2–3 层（层距 90px，下层 α .6）；筛选 → `Trap` 漏斗；**旋转只给齿轮/表盘/转盘**。

## 8. 性能红线（违反会让整片渲染慢 10–50 倍）

- 禁 `feConvolveMatrix`；`filter: blur()` / feGaussianBlur **σ≥1**（σ<0.8 在 Chromium 无效）；SVG filter 加 `colorInterpolationFilters="sRGB"`。
- 单帧 DOM **≤600 节点**、SVG filter 实例 **≤6**、OffthreadVideo **≤1**。粒子/网格用纯函数按 N 生成。
- 完工前 30 帧测渲 `scripts/test_render.sh Gn <起始帧> gN`，应在 **3–12 s**；低于 3 fps 要找原因。

## 9. 自检与交付

- `npx tsc --noEmit` 通过（在 remotion 目录）。
- 出 still：**本档每镜头 2 张**（入场完成帧 + 关键帧），**尺度 0.25（320×180）**，输出到 `<项目根>/stills/Gn/`；只用 `scripts/still.sh Gn <帧号,逗号分隔> <输出目录绝对路径> gN`（**tag 固定 gN，一个组只留一个 bundle**；改代码后先挪走 `build_dev_gN`）。**禁用 `npx remotion still`**（临时 bundle 曾把磁盘写满）。
- 组界帧：本组首镜首帧、末镜末帧各 1 张 → `stills/Gn/boundary_*.png`。
- 看图检查：文字是否被字幕带/进度条/HUD 遮挡、是否溢出画布、颜色是否符合调色板、英文拼写、数字与事实切片一致、元素是否在字幕块起始帧 ±6 内出现、**主角墨迹高度 ≥170px、主角有光、背景无碎屑**。
- `BUILD_NOTES.md`：镜头表（id/帧/文件/内容/**主角 / 主角高度 / 主角的光 / 是否高光 / 运镜 / 配角数 / motion_check 静止%·最长静止**）、复用图元、关键参数、测渲耗时、自检发现、未完成项、对共用层的建议。
- **边做边写盘**（每 1–2 个镜头更新 index.ts 与 BUILD_NOTES），不要攒到最后。最终回复只报：完成镜头数、tsc 结果、测渲 fps、still 目录、需主会话决定的事项。

## 10. 闪烁（GlitchIn）白名单

- **每镜头 ≤1 处 glitch，只给该镜头的重点词**（本片白名单见分镜表「全局约束」）；其余一切文字/标签/胶囊/数字/图标入场用 `SoftIn` / fadeIn / slideUp / scaleIn。**不在表内的镜头一处都不加。**
- 用 `rgbSplit`/`slices` 的重口味只允许片头、章节卡标题、主角登场、片尾大字。
- 终检用 12 帧模板扫描全片，命中数必须等于白名单条数。

# lite 追加的三条硬规范（§12–§14）

> **为什么加**：EXP-01 的 C2F 全片验证发现，C2 在**有机器门禁的规则**上做得比 C0 更狠（静止率 6.7% vs 14.3%），代价全落在**只有人眼兜底的规则**上——最典型的就是**元素互相遮挡**。
> 压缩的本质是「减掉测量手段」。所以 lite 版的正确做法不是「把眼睛还回来」，而是**把原本只有眼睛能发现的事，变成源码里可算的数字**，并用门禁钉住。
> 三条规范都是**零图像成本**的。

## 12. 层序纪律（专治「后出现的元素被先出现的实心块压住」）

**机制**：DOM 里排在后面的元素画在上面。「谁压谁」由**源码里 JSX 的先后顺序**决定，**与入场时间无关**。当后入场的元素被排在前面时，人眼就会看到「它被压在图层背后」——这是**逻辑错误**，不是审美问题。

**规则（硬）**

1. **入场序 = 绘制序。** 若 A 入场帧 < B 入场帧，则 A 在 JSX 里必须写在 B 之前。**新加的元素一律追加到内容块末尾**（不要图省事插到前面）。
2. **实心容器不得压住后入场元素。** `kind=opaque` 的件（非 transparent 的 `Box`、`PaperCard`、`MsgCard`、`Envelope`、`PillCell`、`TagBlock`、`MiniPill`、`ClientBox` …）与任何**入场帧更晚**的元素在**外扩区**（含柔光）不得相交。
3. **确需叠放**（飞入卡压背景图、弹窗压旧内容）时：被压方的入场帧必须 **≤** 施压方，并在 `BUILD_NOTES.md` 写明「X 有意压在 Y 上 + 理由」。**默认禁止反向叠放。**
4. **主角旁放卡片，先按 §1 安全区算，再留 ≥24px 间距**。不要凭"看起来差不多"卡位。
5. **字幕带/HUD 同理**：它们由 G0 用 `layer` 渲染，永远在最上；**任何内容元素的外扩区不得进 y637–690**。

**字距陷阱（实测）**：改主角字号或字距会改变墨迹宽度 → 原来算好的卡位可能不再安全。本片实测：字距 0 → 主角墨迹右缘 **908**；字距 3 → **919**。C0 当年把卡片右移到 910，照抄到 C2F（字距 3）**仍然重叠 9px**。
→ **照抄别处的坐标是危险动作，必须在当前实现上重算。**

**自检**：`python scripts/zorder_audit.py <项目根>/src/shots --gate`；命中 `[高·Z1]` 即违反本节。

## 13. 坐标须字面量（可审计性的前提，不是风格偏好）

`zorder_audit.py` 是**零图像**门禁，它**只能读源码字面量**。任何"运行时才知道"的坐标都会让该元素落进**未解析清单**——**未解析 = 审计盲区 = 有 bug 也不报**。

**规则（硬）**

1. 参与遮挡判定的内容元素，矩形必须**可由源码字面量求得**：直接写数（`x={880}`）或引用 `const NAME = <纯数表达式>`。
2. **禁止**（实测这四种都不可静态求值，一律入盲区）：
   - `x={someFn()}`、`left: {computed}` —— 函数调用
   - `cx={MAP[i].cx}`、`cx={HERO.cx}`、`h={CLIENT.h}` —— **对象属性访问**
   - `x={CARD.x + cardDx}` —— **动态偏移**（哪怕基数是字面量）
   - 把坐标拆到外层 wrapper、内层写 `<PaperCard x={0} y={0} />`

   → **正确写法：把几何抽成「扁平局部常量」**
   ```tsx
   const CARD_X = 420; const CARD_W = 460;   // ✅ 扁平字面量
   <MsgCard x={CARD_X} y={CARD_Y} w={CARD_W} h={CARD_H} />
   ```
   必须用 wrapper 时，**偏移量本身必须是字面量或可解析 `const`**（审计器会尝试归并 wrapper 偏移；失败即入盲区）。
3. **自定义共用件登记（只救得了一部分）**：项目根放 `zorder_parts.json` 登记审计器不认识的共用件（结构见 `scripts/zorder_audit.py` 文件头注释）。
   ⚠ **实测边界**：注册表只能救「几何本身是字面量、只是件不在内置表里」的情况。本项目 C2F 单加一条 `BigNumber` → 覆盖率 **74.0% → 80.0%（仅 +6pp）**；剩下 10 个盲区**全是** `OBJ.prop` 与动态偏移（`MsgCard x={CARD.x + cardDx}`、`ClientBox cx={CLIENT.cx}`、`Envelope`），**注册表救不了，只能按规则 2 改写源码**。
   → 结论：**注册表是补丁，规则 2 的坐标扁平化才是解药。**
4. **交付门槛**：`--gate` 的**可审覆盖率 ≥90%**，且未解析清单为空；非空时每一件都要写进 `BUILD_NOTES.md` 的「已知盲区」并说明为什么不影响本镜。

**为什么较真**：本项目实测 **C0 版覆盖率只有 63.2%**——主角写成 `<CText cx={HERO.cx}>`、卡片坐标被 wrapper 拆走，**审计器在 C0 上"0 命中"其实是瞎**。低覆盖率下的「干净」没有任何证据力。

## 14. 自检与交付补列（补上「元素之间」这个维度）

§9 的自检项都是**单元素**的（主角够大吗 / 有光吗 / 溢出吗）。本节补**元素之间**的维度，并把它变成 BUILD_NOTES 的必填列。

**每镜头必跑（收组前，几秒，零图像）**

```bash
python scripts/zorder_audit.py <项目根>/src/shots --gate   # Z1 层序 · Z2 叠字 · 覆盖率
```

**BUILD_NOTES 镜头表新增三列（必填）**

| 列 | 内容 | 来源 |
|---|---|---|
| **主体墨迹盒** | `x0,y0,x1,y1`（外扩区口径，含柔光） | 审计报告 / 手算 |
| **最大重叠** | 本镜所有配对里最大的重叠 `W×H = 面积 px²`，写清「谁压谁」 | 审计报告 |
| **Z1/Z2** | 命中数（目标 `0`） | 审计报告 |

**收组结论必须显式列出（不许省）**

- `层序命中：高 N / 中 M`（目标 0）
- `可审覆盖率：P%`（门槛 ≥90%）
- `未解析清单：…`（为空才写"无"）
- 若有 `[高]`：**先修再交**，不要留给 QC。修法见 §12 规则 2/3 —— 挪开施压方（右移/下移，按 `zorder_audit` 给出的像素数加 ≥8px 余量），或把施压方的入场帧提前到被压方之前。

**为什么必须落成列**：EXP-01 里 C0 版 `SC06` 的构建者其实**算过**重叠并写进了注释（「卡片 850–1149，重叠 86px」）——但**没有列可填**，信息留在注释里、没进交付物；半年后换一版重建时，**没有任何机制把它带回来**，于是同一个 bug 精确复现（C2F 把卡片放回 880、年份放回 250）。**有列才有承接。**
